## Repository-specific records

### D11 — Jewelmorphism: chromatic depth without false optical claims

**Use when:** When recovering neumorphism-soft-ui-design-system, Morphica crystal surfaces, gem tokens, or prism-like component behavior.

[Recovered intent] This repository's current README identifies Jewelmorphism: soft-shadow depth refracted through gem-like chromatic splitting, internal glow, compression, and spectral highlights. The repository name preserves an earlier neumorphism identity; do not erase that lineage or assume it remains a generic soft-UI kit.

[Design DNA] Amethyst, violet/cyan splits, translucent surfaces, dual-source shadows, inner shadows, short compression and longer release. The intended implementation begins with HTML/CSS and optional lightweight motion.

[Repair resolution — proposed] Distinguish metaphorical tokens—hardness as weight, cleavage as grid—from measured material properties. Build accessible contours and focus independently of low-contrast shadows. Use “gem-inspired appearance” for CSS; reserve refraction/dispersion claims for a defined optical implementation.

[Reimagined horizon] A compact browser-native material family with a CSS baseline and optional shader specimen. The material can be authored, inspected, and adapted without requiring every consumer to run WebGL.

[Carry-forward test] A crystal-inspired control is recognizable in a flat/static fallback, is readable across its composited background, and has a documented difference between chromatic decoration and optical transport.

## Practical continuation contract

1. Re-read current repository instructions and source before implementation. The baseline above identifies this publication, not a permanent execution HEAD.
2. Retain the full design horizon separately from the current demonstrator. Name what the demonstrator preserves, approximates, defers, or cannot prove.
3. Map tokens and controls to actual consumers with explicit units, ownership, accessible alternatives, and observable effect.
4. Complete the relevant interaction/error/cancellation states before promoting a reusable component.
5. Pair source/runtime checks with human correspondence review against the actual visual inspiration.
6. Keep proposed repairs unexecuted until a later implementation records its own revision, checks, and evidence.
